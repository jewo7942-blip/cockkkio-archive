# 콕끼오(CockkkiO) NFC 아카이브 — 가이드

키링 하나로 사진 아카이브 / 럭키드로우까지 이어지는 정적 사이트예요.

- `index.html` → 키링을 태그하면 뜨는 첫 화면. NFC 인식 → 코트 라인 점등 → 카메라 플래시 → 메뉴 2개 카드 등장
- `archive.html` → 사진 갤러리 (카테고리 구분 없는 통합 피드, 매손리 레이아웃)
- `slot.html` → LUCKY SLOT 미니게임 (허브의 럭키드로우 카드가 여기로 연결됨) — 대회 중 남는 상품을 라운드 단위로 추첨
- `draw.html` → 예전 룰렛 방식 (현재 허브에서 링크 안 걸려있음, 안 써도 됨)
- `apps-script.gs.txt` → LUCKY SLOT용 구글시트 백엔드 코드 (7번 항목 참고)

## 1. 사진/영상 넣는 법 — 폰으로 업로드만 하면 끝

`archive.html`의 `REPO_OWNER`는 이미 `jewo7942-blip`으로 채워져 있어요. 저장소 이름을 `cockkkio-archive`가 아닌 다른 이름으로 만드셨다면 `REPO_NAME` 값도 맞춰서 바꿔주세요.

그 다음부터는 대회 당일에도 이렇게만 하면 돼요:

1. 폰에서 GitHub 앱(또는 모바일 웹)으로 저장소 접속
2. `assets/photos` 폴더로 이동 (카테고리 구분 없이 전부 여기 한 곳)
3. Add file → Upload files → 폰 갤러리에서 사진 선택 → 업로드
4. 끝. 새로고침하면 바로 보여요 — 사진이 많아지면 "더 보기" 버튼으로 이어서 로드돼요

파일명 그대로 올리면 돼요. 코드 수정, 개수 세기, 카테고리 고르기 — 아무것도 필요 없어요.

> 참고: 갤러리는 GitHub의 공개 API로 폴더 내용을 그때그때 불러오는 방식이라, 저장소가 **Public**이어야 하고 인터넷 연결이 필요해요.

**당일 여러 명이 같이 올릴 때 참고할 점**

- **아이폰 사진(HEIC) 주의**: 아이폰 기본 사진 형식(.HEIC)은 안드로이드/크롬 등 일부 브라우저에서 안 보일 수 있어요. 되도록 설정 → 카메라 → 포맷을 "높은 호환성"으로 바꾼 뒤 찍은 사진을 올려주세요. 이미 찍은 사진은 공유/저장 시 자동으로 jpg 변환되는 경우가 많아 큰 문제는 없지만, 혹시 사진이 안 보인다는 얘기가 나오면 이걸 먼저 의심해보세요.
- **파일명 겹침 주의**: 여러 사람이 각자 폰에서 올리면 `IMG_0001.jpg`처럼 이름이 우연히 겹칠 수 있어요. 겹치면 GitHub이 기존 사진을 덮어써버려서 먼저 올린 사진이 사라질 수 있어요. 안전하게 가려면 **한 명(운영진)이 다같이 모은 사진을 한 번에 업로드**하는 방식을 추천해요 — 여러 폰 사진을 한 사람 갤러리로 모은 뒤 올리면 앨범 앱들이 대부분 자동으로 이름을 다르게 붙여줘서 겹칠 일이 없어요.

## 2. 배포 — GitHub Pages

1. github.com에서 새 저장소 생성: `cockkkio-archive` (Public)
2. 압축 푼 폴더 **내용물만** 업로드 (index.html 등 — 폴더째 올리지 않기)
3. Settings → Pages → Branch `main` / `root` 설정 → 저장
4. 몇 분 뒤 발급되는 `https://아이디.github.io/cockkkio-archive/` 로 접속 테스트

## 3. 키링에 굽기 — 하나의 세트, 개인 번호 포함

키링은 한 세트만 구우면 돼요. 각 키링마다 아래처럼 번호(id)만 다르게 넣어주세요:

```
.../index.html?id=1
.../index.html?id=2
...
.../index.html?id=103
```

`index.html`이 자기 URL의 `id`를 읽어서 대회안내·아카이브·드로우 3개 링크 전부에 자동으로 붙여줘요. 그래서:
- 아카이브/안내 페이지는 그 번호를 그냥 무시하고
- 럭키드로우(draw.html)만 그 번호로 상품을 결정해요

개인화된 링크라 bit.ly 단축은 큰 의미가 없어요 — GitHub Pages 긴 주소를 그대로 굽는 걸 추천해요. 번호는 스티커/유성펜으로 키링에 표시해두면 나중에 당첨 확인할 때 편해요.

**굽는 법**: NFC Tools 앱 → 쓰기(Write) → 레코드 추가 → URL/URI → 번호 넣어 태그 → 저장. 굽기 끝나면 "쓰기 잠금(lock)" 설정 추천.

## 4. LUCKY SLOT — slot.html (구글시트로 라운드 관리)

대회 중 남는 상품이 생길 때마다 새 라운드를 열어서 진행하는 미니게임이에요. 코드를 안 건드리고 **구글시트에서만** 라운드를 열고 닫을 수 있어요.

**한 번만 할 일 (시트 만들기)**

1. 구글시트 새로 만들기
2. 탭 2개 생성: `Rounds`, `Plays`
3. `Rounds` 탭 1행에 헤더 입력:
   `roundNumber | status | prizeLabel | winRate | winnerKeyringId | closedAt`
4. 2행부터 라운드 데이터 입력, 예:
   `1 | OPEN | 음료 1개 | 0.15 |  | `
5. `Plays` 탭 1행에 헤더만 입력: `roundNumber | keyringId | win | kind | at` (나머지는 자동 기록됨)
6. 상단 메뉴 **확장 프로그램 → Apps Script**
7. 기본 코드 지우고 `apps-script.gs.txt` 내용 전체 붙여넣기 → 저장
8. **배포 → 새 배포** → 유형: 웹앱 / 실행: 나 / 액세스: 전체 허용(Anyone)
9. 배포 후 나오는 **웹 앱 URL 복사**
10. `slot.html` 안의 `APPS_SCRIPT_URL = ""` 자리에 그 주소 붙여넣기

**대회 당일 라운드 운영법**

- 새 상품이 생기면 `Rounds` 탭에 새 줄 추가하고 `status`를 `OPEN`으로
- 이전 라운드는 신경 안 써도 돼요 — 시스템은 항상 **가장 마지막 줄**을 현재 라운드로 봐요
- 누군가 당첨되면 `status`가 자동으로 `CLOSED`로 바뀌고 `winnerKeyringId`에 당첨자 번호가 기록돼요
- 당첨 확률은 `winRate` 칸 숫자로 조절 (0.15 = 15%)
- 다음 라운드 미리 예고하고 싶으면 새 줄을 `COMING_SOON`으로 넣어두기

`APPS_SCRIPT_URL`을 아직 안 채웠으면 자동으로 로컬 데모 모드(15% 고정 확률)로 동작하니, 시트 연동 전에도 테스트에는 문제없어요.

지금은 허브에서 안 쓰지만 남겨뒀어요. 키링 번호별로 상품을 미리 코드에 고정해두는 방식이라, 재고가 실시간으로 줄어드는 걸 반영 못해요. LUCKY SLOT과 용도가 다르니 필요하면 참고만 하세요.

## 7. 색/폰트 바꾸고 싶다면

각 파일 상단 `:root { ... }` 안의 값만 바꾸면 전체 톤이 바뀌어요.

- `--court` : 배경 코트 그린
- `--accent`: 포인트 컬러 (라임)
- `--chalk` : 텍스트/라인 컬러
